# vibe-coding-mentor

**[English version →](README.en.md)**

Скил для Claude Code, который **учит строить софт вместе с агентом**, а не просто отдаёт код.

Разворачивает обычный поток вайбкодинга: не «агент пишет — человек соглашается»,
а «человек формулирует и проверяет — агент объясняет и страхует».

> **Язык:** содержимое скила на русском. Триггеры в `description` — русские и английские.
> **Статус:** рабочий, но не прогонялся через тестирование сабагентами (см. «Ограничения»).

## Два скила в репозитории

| Скил | Зачем | Вызов |
|------|-------|-------|
| `vibe-coding-mentor` | Ведёт по шагам, объясняет, проверяет понимание | по триггерам или `/vibe-coding-mentor` |
| `vibecoding` | Диагностика проекта: что отсутствует и что делать | `vibecoding сделай диагностику` |

## Установка

```bash
npx skills add AzamatRaimbekov/vibe-coding-mentor -g -y            # оба скила
npx skills add AzamatRaimbekov/vibe-coding-mentor@vibecoding -g -y # только диагностика
```

Или вручную — скопировать папки из `skills/` в `~/.claude/skills/`.
После установки скилы доступны в новой сессии.

## Диагностика: `vibecoding`

```
vibecoding сделай диагностику
```

Запускает `scripts/diagnose.sh` — 30+ проверок в девяти разделах: Git и секреты ·
воспроизводимость · скрипты · тесты · типы · UX отказов · данные · документация · CI.
Тип проекта определяется автоматически, неприменимое помечается `SKIP`.
Ни одна упавшая проверка не роняет остальные.

Отчёт человеку выдаётся не таблицей, а по структуре: строка итога → **максимум три**
пункта «чинить сейчас» (каждый через последствие, а не через факт) → остальное в план →
обязательный раздел «что уже хорошо» → один вопрос в конце.

Отдельный раздел скила — **ложные срабатывания**: скрипт проверяет наличие файлов,
а не замысел. Найденный в истории `API_KEY` чаще документация, чем ключ; seed может
лежать нестандартно. Правило: сомневаешься — открой глазами. Две выдуманные проблемы,
и скил перестанут запускать.

Диагностика **не чинит** — показывает состояние и предлагает порядок.

## Зачем

Вайбкодинг ломается не на генерации кода, а на **отсутствии обратной связи**.
Агент пишет, человек соглашается, никто не проверяет. Через месяц никто, включая автора,
не может объяснить, как это работает.

Базовый принцип скила: **пользователь должен уметь объяснить каждое принятое изменение.**
Если не может — шаг был слишком большим.

## Два входа

| Пользователь говорит | Вход | Что происходит |
|----------------------|------|----------------|
| «сделай / доделай / почини X» | **Задача** | Цикл наставничества из 8 шагов |
| «хочу стать data scientist», «с чего начать» | **Цель** | Роадмап по направлению |

### Роадмап

Начинается с четырёх вопросов — откуда стартуем · куда хотим · сколько времени в неделю ·
что зажигает — и **не выдаёт план до ответов**: без них это фантазия, а не роадмап.

Дальше 4–6 этапов, где каждый описан **артефактом**, а не темой:

```
Этап 2. Первый анализ на реальных данных

Что построишь: ноутбук, который берёт открытые данные о ценах на жильё,
чистит их и отвечает, что сильнее влияет на цену — площадь или район.

Зачем перед следующим: пока не поработаешь с грязными данными, машинное
обучение будет выглядеть магией, а не инструментом.

Готово, когда: можешь объяснить вывод человеком без графиков, одной фразой.
```

Критерий «готово» обязан быть проверяемым. «Изучить pandas» — не критерий.

Скилы под каждый этап ищутся **фактическим поиском**, а не по памяти, и ставятся
только под текущий этап: до третьего человек дойдёт через месяцы, и половина
установленного к тому времени устареет.

Направления со стартовыми запросами: Data Science, аналитика, ML, Frontend, Backend,
DevOps, мобильная разработка, безопасность. Плюс таблица проверенных точек входа —
Python, pandas, NumPy, scikit-learn, PyTorch, Kaggle, SQL, Git, Docker, MDN.

Чего роадмап не делает: не обещает сроки трудоустройства и зарплату, не выдаёт
двадцать тем «для полноты», не называет курсы по памяти.

## Цикл

Один проход = одна фича.

| # | Шаг | Агент | Ученик |
|---|-----|-------|--------|
| 0 | Уровень | Спрашивает, что уже знакомо | Отвечает честно |
| 1 | Намерение | Помогает сформулировать «готово, когда…» | Пишет критерии приёмки |
| 2 | Аудит | Прогоняет чек-лист проекта | Выбирает 1–2 пробела |
| 2.5 | Инструменты | Проверяет MCP, скилы и плагины, называет чего нет | Решает: чинить или работать с ограничением |
| 2.6 | Подбор | Ищет готовый скил под задачу, объявляет какой берёт | Видит, чем задача будет решаться |
| 3 | Границы | Показывает, где домен / IO / UI | Говорит, куда положить код |
| 4 | **Красный тест** | Пишет падающий тест | **Предсказывает, почему упадёт** |
| 5 | Реализация | Минимальный код до зелёного | Читает диф и называет, что он делает |
| 6 | Проверка | Запускает команды, показывает вывод | Видит доказательство |
| 7 | Разбор | 3 строки: усвоено / шатко / дальше | Задаёт вопросы |

Шаг 4 — точка обучения. Предсказание вслух **до** запуска встраивает модель поведения кода.
Согласие с готовым ответом — нет.

Каждый пункт — **пользой, а не названием инструмента**. Не «умею работать
с Playwright MCP», а «открою сайт и покажу, как он выглядит»: название человеку
без опыта не говорит ничего, польза говорит всё. Семь-девять пунктов.

Три пункта про самостоятельность обязательны — именно необходимость настраивать
инструменты отпугивает новичков сильнее всего.

Пункт 🧠 сформулирован **честно и намеренно узко**: память между сессиями даёт
плагин `claude-mem`, новые навыки агент действительно пишет сам. Но модель на
пользователе **не переобучается**, и обещать это скилу запрещено — невыполненное
обещание обесценивает всё остальное, что он говорит.

Отметка о состоявшемся знакомстве — `~/.claude/.vibecoding-welcomed`. Удалить
файл, чтобы поздороваться заново. Дальше — короткая версия:

> 👋 Привет! Я Азамат, твой вайб-кодер-учитель.
>
> 🌱 Не переживай, если что-то непонятно — это нормально, я объясню любое слово.

>
> Расскажи, что хочешь построить или чему научиться?

Дальше имя не повторяется в каждом сообщении — представился один раз, этого хватает.
Речь от первого лица: «я проверю», «я покажу», «давай сделаем» — не «система выполнит».

Спросят прямо, человек это или программа — ответ честный: ИИ-помощник по имени Азамат.
Врать нельзя даже в мелочи, доверие ученика единственное, на чём держится обучение.

## Видно, что происходит

Каждое действие с инструментами объявляется **до** запуска — человек не гадает,
почему пауза:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🚀  ЗАПУСКАЮ СКИЛ — vibecoding  ✨
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Под баннером строка простым языком, зачем это и сколько займёт. В конце — `✅ ГОТОВО`.

🚀 запуск скила · 🩺 диагностика · 🔍 поиск скила · 📦 установка · 🔌 проверка
подключений · 🧪 тесты · 🗺️ роадмап

Баннер ставится **только под действие с инструментами**. На обычную реплику — нет:
иначе он превращается в шум и перестаёт замечаться.

## Автозапуск на каждый промпт

В репозитории лежит `hooks/vibecoding-always.sh`. Он подключается один раз
и после этого пропускает **каждый** запрос через правила скила — язык, баннеры,
самостоятельность, поддержка, финальный блок «что сделать тебе».

```bash
mkdir -p ~/.claude/hooks
cp hooks/vibecoding-always.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/vibecoding-always.sh
```

Затем добавить в `~/.claude/settings.json` в массив `hooks.UserPromptSubmit`:

```json
{ "hooks": [{ "type": "command",
              "command": "bash \"$HOME/.claude/hooks/vibecoding-always.sh\"" }] }
```

Хук молчит, если скил не установлен, — на чужой машине он ничего не сломает.

## Проверка базового набора

`skills/vibecoding/scripts/ensure-tools.sh` проверяет, чем агент вообще может
работать: плагины (superpowers, claude-mem, frontend-design, vercel), скилы
(agent-browser, find-skills, graphify, stitch-*), MCP (playwright, 21st).

```bash
bash ensure-tools.sh            # только проверить
bash ensure-tools.sh --install  # доставить недостающее самому
```

Отдельно помечает строками `ЧЕЛОВЕК|авторизация|…` то, что требует входа через
браузер и не может быть сделано за него.

## Делает сам, а не поручает

Ученик пришёл строить, а не администрировать. Скил ставит скилы, плагины и MCP-серверы
**сам**, создаёт своих агентов сам — и объявляет каждое действие:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅  Я УСТАНОВИЛ — stitch-generate-design  🎉
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
> Теперь я умею рисовать макеты экранов по описанию словами.

`✅🎉 Я УСТАНОВИЛ` · `🛠✨ Я СОЗДАЛ` · `🔌⚡ Я ПОДКЛЮЧИЛ` · `🙋⚠️ НУЖЕН ТЫ`

На человека перекладывается **только физически невозможное** — список закрытый:
вход через браузер (OAuth), секретные ключи, платные подписки. И баннер `🙋 НУЖЕН ТЫ`
обязан объяснить, **почему агент не может сам** — без этого выглядит как лень.

**Проверка на диске, а не по выводу команды.** Установщик печатает «Installation
complete» и при этом может не поставить ничего в нужное место — реальный случай
с `npx skills add`, который сыплет ошибками чужого формата, но для Claude Code ставит
всё правильно. Не проверил `ls -d ~/.claude/skills/<имя>` — не объявляй установку.
Ложное объявление хуже молчания: человек рассчитывает на возможность, которой нет.

В конце работы — таблица «сделал сам / нужен ты». А если человеку всё же осталось
действие, которое может сделать только он, — оно идёт **последним блоком** ответа,
нумерованным списком, максимум три пункта, каждый с объяснением зачем:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🙋  ЧТО СДЕЛАТЬ ТЕБЕ  ⚠️
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Набери `/mcp` и подтверди вход в браузере
   — без этого я не вижу логи публикации
```

Больше трёх пунктов означает, что агент свалил на человека свою работу. Пустой
список в большинстве ответов — признак правильной работы; тогда пишется одна
строка `✅ От тебя ничего не нужно, всё готово`.

## Поддержка

Человек, который учится, по умолчанию боится сделать неправильно. Скил снимает
страх раньше, чем он помешает: 🌱 в начале работы, 🤗 когда ошибся, 😌 когда застрял,
🛟 когда сломалось.

При ошибке порядок обязателен — **сначала снять напряжение, потом разбор**:

```
🤗 Так ошибаются вообще все, кто делает это впервые — правда.

🟡 ТАК ЛУЧШЕ НЕ ДЕЛАТЬ
Что произошло: … · Чем грозит: … · Как надо: …
```

Похвала — **за конкретное дело, а не за согласие**. «Ты молодец» после каждой реплики
обесценивает саму похвалу: за что хвалят, перестаёт быть понятно. Хвалят за
предсказание, верный вопрос, пойманное заблуждение — и всегда говорят, что именно
было хорошо. За «ок» не хвалят: это учит соглашаться.

Прямой запрет: не хвалить за неправильное. Ложная похвала вскроется на следующем шаге.

## Обратная связь: зелёный и жёлтый

Ученик видит, где он молодец, и где свернул не туда — **до** того, как ошибка станет привычкой.

```
🟢 ХОРОШО ПОЛУЧАЕТСЯ
> Ты сам заметил, что цена должна копироваться в заказ, а не браться ссылкой.
> Это ровно то различие, на котором ломаются реальные магазины.

🟡 ТАК ЛУЧШЕ НЕ ДЕЛАТЬ
> Что произошло: проверка наличия и списание идут двумя отдельными шагами.
> Чем грозит: двое покупателей одновременно купят последнюю единицу.
> Как надо: объединить в одну операцию — покажу как.
```

Зелёный называет **конкретное действие**, а не человека: «молодец» — пустой звук,
«ты сам заметил X» — обратная связь. Жёлтый обязан содержать три части, и третья —
«как надо»; без неё это претензия, а не обучение. По одному каждого за шаг.
Ни одного за весь шаг — красный флаг: значит ученик просто соглашался.

> Настоящего цвета в терминале нет — вывод рендерится как markdown. Цвет передаётся
> кружком и капсом.

## Разговор с человеком не из IT

Базовое допущение: **ученик не программист.** Каждый термин объясняется при первом
упоминании — жирным, одним предложением, с аналогией и ссылкой на документацию.
Не больше двух новых терминов на сообщение.

Слова «просто» и «очевидно» — red flag: они означают, что объяснение пропущено.
Команда никогда не даётся без трёх вещей: где запускать, что делает, что должно появиться.

**Вопросы — по тем же правилам.** Вопрос это часть объяснения, а не пауза в нём.
Каждый вариант ответа объясняется дважды: что это и что произойдёт, если выбрать.

| Плохо | Хорошо |
|-------|--------|
| «Vitest или Playwright?» | «Проверять код по кусочкам — быстро, ловит мелкие ошибки. Или целиком через настоящий браузер — медленнее, зато ловит то, что видит пользователь» |
| «Какой ORM?» | «Чем работать с базой данных? Это выбор инструмента, который превращает твой код в запросы к базе» |

Вопрос, ответ на который человек не может знать по своему уровню, не задаётся вообще:
вместо него — объяснение развилки и вариант с обоснованием.

Исключение: пользователь сам пишет технически и просит короче — правило защищает
от непонимания, а не навязывает урок.

Внутри — словарь из 20 понятий (коммит, ветка, пропсы, миграция, деплой…) и таблица
ссылок на официальную документацию: MDN, learn.javascript.ru, React, Next.js, Prisma,
Vitest, Playwright, Tailwind, Vercel, Supabase, Zod, W3C.

## Подбор скилов под задачу

Каждая задача начинается с вопроса «есть ли на это готовый скил». Порядок жёсткий:
что уже установлено → `npx skills find` → и только потом писать свой.

Найденное проверяется по трём критериям (установки, автор, содержимое — скил выполняется
с полными правами агента). Свой скил пишется, только если поиск пуст, приём понадобится
снова и его нельзя заменить строкой в `CLAUDE.md`. Три новых скила за сессию — признак,
что агент обустраивает рабочее место вместо работы.

## Что проверяется

### Артефакты проекта — `references/project-checklist.md`

Восемь разделов, у каждого пункта команда проверки и колонка **«цена промедления»** —
чтобы ответ был не «так принято», а «вот что сломается»:

воспроизводимость · гигиена репозитория (секреты в истории) · границы слоёв · тесты ·
данные и миграции · UX отказов (404, crash fallback, offline) · ADR и документация · CI

Внизу — таблица «что достаточно на этапе». От прототипа не требуется прод-уровень,
но проверка на утёкшие секреты обязательна с первого коммита.

### MCP-серверы — `references/deploy-mcp.md`

Vercel · Supabase · 21st.dev, плюс фолбэки на CLI.

Ключевая мысль: **отсутствующий сервер честен, а `Needs authentication` — врёт.**
Его не видно как проблему, инструменты в списке есть, каждый вызов падает — и человек
уходит чинить код вместо авторизации.

### Скилы и плагины — `references/required-skills.md`

Четырнадцать скилов, разбитых по строгости. Отсутствие процессного ядра
(`test-driven-development`, `verification-before-completion` и др.) — **стоп**,
а не «работаем с ограничением»: без них цикл нечем выполнять.

Плагины проверяются отдельной командой (`claude plugin list`) — в списке скилов их не видно.
`claude-mem` обязателен: обучение идёт неделями, без памяти каждая сессия стирает предыдущую.

### Понятия — `references/concepts.md`

Девять мест, где спотыкаются чаще всего: контракты, границы слоёв, снапшот против ссылки,
гонки и условное обновление, идемпотентность, ошибки как часть поведения,
отражённый текст, доказательство вместо утверждения.

Каждое — в формате «какую боль лечит → как выглядит → вопрос на проверку понимания».

## Защита от вырождения

Скил, который учит дисциплине, первым же её и теряет. Поэтому внутри:

- **Таблица рационализаций** — 15 отговорок с контраргументами: «объясню позже»,
  «ученик сказал ок, значит понял», «быстрее написать самому», «логи примерно такие бывают»
- **Red flags** — при них агент откатывается на шаг назад: три подряд «ок» без вопросов,
  50 строк без остановки, «работает» без вывода команды, деплой без проверки MCP,
  необъяснённый термин, слово «просто» в тексте, шаг без единого 🟢 или 🟡
- **Выключатель** — прямое указание пользователя главнее скила. «Просто сделай» → делает,
  но заканчивает разбором на три строки

## Что должно стоять у вайбкодера

Подборка внутри скила — `references/recommended-stack.md`, собрана фактическим поиском
по `npx skills find` (снимок на 28.08.2026).

**Сначала плагины** — они дают основу и ставятся другой командой:

```bash
claude plugin install superpowers@claude-plugins-official   # brainstorming, TDD, verification
claude plugin install claude-mem@thedotmack                 # память между сессиями
claude plugin install frontend-design@claude-plugins-official
claude plugin install vercel@claude-plugins-official
```

**Потом четыре скила**, которых не хватает почти каждому вайбкод-проекту:

```bash
npx skills add vercel-labs/agent-skills@deploy-to-vercel -g -y      # 115.7K — публикация
npx skills add addyosmani/web-quality-skills@accessibility -g -y    #  48.2K — доступность
npx skills add trkbt10/indexion-skills@indexion-readme -g -y        #   5.1K — README
npx skills add open-mercato/skills@om-root-cause -g -y              #    743 — причина бага
```

Дальше — **работать**, и доставлять под стек по мере надобности: TypeScript, React/Next.js,
security review, web vitals, refactor, commit messages, PR review, документация.
Полные таблицы с числами установок — в файле скила.

Честно о списке: числа установок означают популярность, **не качество**, и стареют.
Скил выполняется с полными правами агента — открывай `SKILL.md` глазами перед установкой.
Тридцать установленных скилов не делают кодером; четыре используемых — делают.

Чего в подборке нет: универсального скила на тесты (всё найденное заточено под чужие
стеки — работает `test-driven-development` из `superpowers`), базы данных и планирования
(слабее, чем `brainstorming` и `writing-plans` оттуда же).

## Самообучение

Модель не переобучается — но инструкции, по которым работает скил, накапливают опыт.
Два файла, которые скил ведёт сам и читает в начале каждой сессии:

**`references/lessons.md` — мои ошибки.** Формат жёсткий: что случилось · **почему
ошибся** · правило на будущее. Средняя часть обязательна: без неё запомнится
частность вместо причины, и урок не перенесётся на похожий случай.

```bash
scripts/learn.sh "Название" "Что случилось" "Почему ошибся" "Правило"
```

Четыре урока записаны с первого дня работы — например, что вывод установщика
не равен результату установки, и что индекс каталога скилов устаревает быстрее,
чем репозитории.

**`references/student-profile.md` — как работать с этим человеком.** Пять разделов:
что уже уверенно знает · что даётся тяжело · как ему удобно работать · куда движется ·
принятые решения.

```bash
scripts/note-student.sh <знает|трудно|стиль|цели|решения> "наблюдение"
```

Записывается **наблюдение, а не догадка**: не «наверное, слабо знает базы данных»,
а «сам написал условие для гонки при списании товара». Основание — то, что человек
сделал, а не то, что о нём подумали.

Раздел «что даётся тяжело» стареет быстрее всех. Прежняя трудность пройдена —
строка переносится в «знает», и об этом говорится вслух: это лучшая похвала
из возможных, потому что она измеримая.

Оба скрипта отказываются писать дубль. После записи — строка `🧠 Записал…`,
чтобы человек видел, что его слышат.

## Ограничения

- **Не оттестирован.** По методике `writing-skills` скил положено прогонять через
  сабагентов: смотреть, как они обходят правила без него, и затыкать конкретные дыры.
  Этот этап не пройден — часть формулировок может оказаться дырявой на практике.
- **Русский язык.** Тело скила на русском, что сужает аудиторию.
- **Заточен под Claude Code.** Проверки используют `claude mcp list` и раскладку
  `~/.claude/skills/`.

Отчёты о том, где скил дал слабину, полезнее звёзд — открывайте issue.
