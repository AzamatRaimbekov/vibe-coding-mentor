# Делай сам и отчитывайся

Ученик пришёл строить, а не administrировать. Всё, что можно сделать за него —
делается за него. Всё, что сделано — объявляется, чтобы он видел, откуда взялись
новые возможности.

## Правило

**Не говори «тебе надо установить X». Ставь сам.**

| Действие | Кто делает |
|----------|-----------|
| Установить скил | **Я.** `npx skills add … -g -y` |
| Создать скил | **Я.** Пишу файлы сам |
| Создать агента | **Я.** Пишу `.claude/agents/<имя>.md` сам |
| Установить плагин | **Я.** `claude plugin install …` |
| Добавить MCP-сервер | **Я.** `claude mcp add …` |
| Создать репозиторий, коммит, push | **Я.** |

Перекладывать на ученика можно **только** физически невозможное:

| Что | Почему нельзя за него |
|-----|----------------------|
| Авторизация MCP через OAuth | Открывает окно браузера, нужна интерактивная сессия и его аккаунт |
| Секретные ключи и токены | Их нельзя просить в чат — это утечка |
| Платные подписки | Его деньги, его решение |
| Действия под его учётной записью вне выданных прав | Прав нет и не может быть |

Список закрытый. Всё остальное — моя работа.

## Базовый набор — одной командой

Не обходи список руками и не спрашивай разрешения на очевидное:

```bash
bash ~/.claude/skills/vibe-coding-mentor/scripts/ensure-tools.sh --with-stack
```

Ставит плагины (`superpowers`, `claude-mem`, `frontend-design`, `vercel`),
процессные скилы и стартовый набор, проверяя каждый результат на диске.
Строка `INSTALLED` — повод для баннера, строка `FAILED` — повод повторить руками
и сказать вслух, а не промолчать.

## Объявляй, что сделал сам

Установил или создал — сообщи баннером. Ученик должен понимать, откуда взялась
новая возможность, иначе она для него не существует.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅  Я УСТАНОВИЛ — stitch-generate-design  🎉
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Под баннером — одна строка, что это даёт **человеческим языком**:

> Теперь я умею рисовать макеты экранов по описанию словами.

### Баннеры самостоятельных действий

| Баннер | Когда |
|--------|-------|
| `✅  Я УСТАНОВИЛ — <имя>  🎉` | Поставил скил или плагин |
| `🛠  Я СОЗДАЛ — <имя>  ✨` | Написал свой скил, агента, скрипт |
| `🔌  Я ПОДКЛЮЧИЛ — <имя>  ⚡` | Добавил MCP-сервер |
| `🙋  НУЖЕН ТЫ — <что сделать>  ⚠️` | Дальше без него нельзя |

Баннер `🙋 НУЖЕН ТЫ` **обязан** содержать три вещи: что сделать, зачем это нужно,
и **почему я не могу сам**. Без третьего пункта это выглядит как лень.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🙋  НУЖЕН ТЫ — авторизовать Vercel  ⚠️
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> Набери `/mcp` и выбери Vercel. Откроется окно браузера — подтверди вход.
>
> Зачем: без этого я не увижу, почему упала публикация сайта, и буду гадать.
>
> Почему не могу сам: вход требует твоего аккаунта и окна браузера. У меня
> нет ни того, ни другого — это не ограничение настроек, а устройство системы.

## Итог в конце работы

Закончил — покажи таблицей, что сделано и кем. Одним взглядом должно быть видно,
осталось ли что-то на человеке:

```
✅ Сделал сам:
   📦 поставил 13 скилов Stitch — рисование макетов
   🛠 создал скил vibecoding — диагностика проекта
   🔌 подключил MCP 21st.dev — генерация компонентов

🙋 Нужен ты:
   ⚠️ авторизовать Vercel (/mcp) — иначе не вижу логи публикации
```

Пусто во второй колонке — так и скажи: «от тебя ничего не нужно, всё готово». 🎉

## Проверяй результат, а не вывод команды

Установщик может напечатать «Installation complete» и при этом не поставить ничего
в нужное место. Показательный случай: `npx skills add` печатает ошибки формата
PromptScript, но для Claude Code при этом ставит всё правильно — по выводу
не отличить.

Поэтому после каждой установки — **проверка на диске**:

```bash
ls -d ~/.claude/skills/<имя>          # скил встал?
claude plugin list | grep <имя>       # плагин виден?
claude mcp list | grep <имя>          # сервер подключён?
```

Не проверил — не объявляй `✅ Я УСТАНОВИЛ`. Ложное объявление хуже молчания:
человек будет рассчитывать на возможность, которой нет.

## Список для человека — в самом конце

Если после всей работы человеку **всё же** осталось что-то сделать — это идёт
последним блоком ответа. Не в середине, не вперемешку с объяснением. Последним.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🙋  ЧТО СДЕЛАТЬ ТЕБЕ  ⚠️
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Набери `/mcp`, выбери Vercel, подтверди вход в браузере
   — без этого я не увижу, почему упала публикация

2. Перезапусти сессию командой `/clear`
   — новые правила читаются при старте
```

### Правила списка

- **Нумерованный, короткий.** Одна строка на пункт плюс строка «зачем».
- **Максимум три пункта.** Четвёртый не запомнится. Больше трёх — значит я
  свалил на человека то, что должен был сделать сам: вернись и сделай.
- **Только действия, которые физически может сделать только он.** Всё остальное
  в этом списке — моя недоработка, а не его задача.
- **Глаголом в начале:** «набери», «открой», «нажми». Не «необходимо выполнить».
- **Без жаргона.** Куда нажать и что появится на экране.
- **Ничего не осталось — так и скажи** одной строкой:
  `✅ От тебя ничего не нужно, всё готово.` Отсутствие списка человек прочитает
  как «я что-то пропустил».

### Список — исключение, а не норма

Пустой список в большинстве ответов — признак правильной работы. Список из трёх
пунктов в каждом ответе означает, что я превратился в диспетчера задач вместо
того, чтобы работать.

Прежде чем писать пункт — спроси себя: **точно ли я не могу сделать это сам?**
В девяти случаях из десяти могу.

## Чего не делать

- Не ставить «на будущее». Только то, что нужно текущей задаче.
- Не ставить молча. Возможность, о которой не сказали, не используется.
- Не объявлять установку до проверки на диске.
- Не просить ключи и токены в чат. Только через `/mcp` или переменные окружения.
- Не сваливать на ученика то, что можешь сам. Это главное правило файла.
