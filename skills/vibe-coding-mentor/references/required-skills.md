# Обязательные скилы

Читай на шаге «Инструменты», вместе с `deploy-mcp.md`. MCP отвечает за доступ к внешнему
миру, скилы — за то, как ведётся сама работа. Дыры в обоих проявляются одинаково: агент
не отказывается, а тихо делает хуже.

## Как устроена установка на этой машине

Скилы живут в `~/.claude/skills/` (глобально) или `.claude/skills/` (в проекте).
Часть установок кладёт туда **симлинки** на мастер-копию в другом каталоге. Битый симлинк
выглядит в `ls` как существующая папка, но не читается — поэтому проверять надо через
`[ -d ]` (следует по ссылке), а не через `-e` или глазами по `ls`.

Установка недостающего:

```bash
claude plugin install superpowers@claude-plugins-official  # brainstorming, writing-plans, TDD, ...
npx skills find <название>              # поиск остального в экосистеме
```

Если скилы пришли из общего набора (ruflo, корпоративный marketplace, свой форк) —
восстанавливай тем же способом, которым ставил изначально, а не поштучно.

## Проверка

```bash
cd ~/.claude/skills
for s in find-skills frontend-agent frontend-error-ux design-system-steward \
         backend-engineering backend-code-review code-reviewer \
         brainstorming writing-plans using-superpowers \
         test-driven-development systematic-debugging verification-before-completion \
         project-documentation-wiki; do
  [ -d "$s" ] || echo "НЕТ: $s"
done
```

Молчание — всё на месте. Не печатай полный список, когда всё в порядке: это шум.

## Что именно проверять и зачем

### Ядро процесса — без них разваливается сам цикл наставничества

| Скил | Шаг цикла | Что ломается без него |
|------|-----------|-----------------------|
| `using-superpowers` | все | Не срабатывает маршрутизация — процессные скилы просто не подключаются |
| `brainstorming` | 1. Намерение | Начинаем кодить, не договорившись, что строим |
| `writing-plans` | 1. Намерение | Многошаговая задача идёт без плана, шаги теряются |
| `test-driven-development` | 4. Красный тест | Главный обучающий шаг выполнять нечем |
| `systematic-debugging` | — | На баг летим чинить симптом вместо причины |
| `verification-before-completion` | 6. Проверка | «Готово» без доказательства — самая дорогая привычка |
| `project-documentation-wiki` | 7. Разбор | Знание остаётся в чате и теряется вместе с ним |

**Отсутствие любого из ядра — это стоп.** Не «работаем с ограничением», а чиним сначала:
без них этот скил обещает то, чего не может.

### Домен — нужны только когда задача их касается

| Скил | Когда нужен | Что ломается без него |
|------|-------------|-----------------------|
| `frontend-agent` | UI, React, Next.js | Нет маршрутизации по фронтенду, компаньоны не подключаются |
| `frontend-error-ux` | любой экран | 404, crash fallback, offline и ошибки форм забываются молча |
| `design-system-steward` | вёрстка | Хардкод цветов и размеров вместо токенов |
| `backend-engineering` | API, сервисы, БД | Нет роутера к конкретным `backend-*` скилам |
| `backend-code-review` | ревью бэкенда | Уходят проблемы прав доступа и целостности данных |
| `code-reviewer` | перед мержем | Ревью «на глаз» вместо чек-листа |

Отсутствие доменного скила при задаче не из его области — не проблема. Молчи о нём.

### Плагины — ставятся отдельно от скилов

Плагин приносит сразу пачку скилов, агентов и MCP-серверов. Проверяется **другой**
командой — в списке скилов его не видно:

```bash
claude plugin list 2>&1 | grep -E '^\s+❯' | sed 's/❯ //'
```

| Плагин | Что даёт | Что ломается без него |
|--------|----------|-----------------------|
| `claude-mem` | Память между сессиями | Каждая новая сессия начинается с нуля; ученик пересказывает контекст заново |
| `superpowers` | Процессное ядро: brainstorming, writing-plans, TDD, verification | Разваливается сам цикл наставничества — это стоп |
| `frontend-design` | Визуальная часть интерфейсов | UI выходит шаблонным |
| `vercel` | MCP для деплоя и логов | См. `deploy-mcp.md` |

Установка: `claude plugin install <имя>@<marketplace>`, затем перезапуск сессии.

**`claude-mem` — обязателен для обучения.** Учеба идёт неделями, а не одной сессией.
Без памяти каждый заход стирает предыдущий, и разбор из шага 7 не накапливается ни во что.

### Разведка

| Скил | Когда нужен |
|------|-------------|
| `find-skills` | **Всегда.** Каждая задача начинается с вопроса «есть ли на это готовый скил» |
| `writing-skills` | Готового не нашлось, а приём понадобится снова |

`find-skills` — не факультатив. Без него агент решает незнакомую задачу с нуля там,
где в экосистеме лежит готовый проверенный скил. Порядок действий: `references/skill-sourcing.md`.

## Осторожно с именами

Названия скилов не совпадают с тем, как о них говорят вслух. Проверяй по точному имени папки,
иначе проверка соврёт «нет» на установленном скиле:

| Говорят | Реальное имя |
|---------|--------------|
| find-skill | `find-skills` |
| frontend-skill | `frontend-agent` |
| backend-skill | `backend-engineering` |
| superpowers | `using-superpowers` + `brainstorming` + `writing-plans` (три отдельные папки) |

## Как докладывать

Только пропуски, и сразу с последствием:

```
НЕТ: test-driven-development  → шаг 4 (красный тест) выполнять нечем — это стоп
НЕТ: frontend-error-ux        → 404 и crash fallback придётся держать в голове
```

Если всё на месте — одна строка «скилы на месте», без перечисления. Полный список из
четырнадцати галочек ничего не сообщает и утомляет.
