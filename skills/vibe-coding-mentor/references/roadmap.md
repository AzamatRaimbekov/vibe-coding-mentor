# Роадмап: путь в направление

Второй вход в скил. Обычный вход — «сделай задачу». Этот — «хочу стать X».
Триггеры: «хочу стать data scientist», «с чего начать», «как войти в бэкенд»,
«составь план обучения».

Роадмап — не список курсов. Это **последовательность вещей, которые ты построишь**,
где каждая следующая опирается на предыдущую.

## Шаг 1. Четыре вопроса, не больше

Задай их одним сообщением и жди ответа. Без ответов роадмап будет фантазией.

1. **Откуда стартуем.** Программировал раньше? Excel, SQL, что-то ещё?
2. **Куда хотим.** Первая работа? Смена профессии? Свой проект? Это разные пути.
3. **Сколько времени в неделю.** 5 часов и 25 часов — разные планы, не разная скорость.
4. **Что зажигает.** Данные о людях, финансы, картинки, тексты? Мотивация кончается
   раньше способностей — направление интереса важнее оптимального маршрута.

Не спрашивай про сроки «за сколько месяцев». Честный ответ зависит от пункта 3,
и называть цифру до него — обман.

## Шаг 2. Форма роадмапа

Четыре-шесть этапов, не больше. Длинный список парализует.

Каждый этап описывается **одинаково**, и первым идёт артефакт, а не тема:

```
### Этап 2. Первый анализ на реальных данных

**Что построишь:** ноутбук, который берёт открытые данные о ценах на жильё,
чистит их и отвечает на вопрос «что сильнее влияет на цену — площадь или район».

**Зачем это перед следующим этапом:** пока не поработаешь с грязными данными,
машинное обучение будет выглядеть магией, а не инструментом.

**Что придётся освоить:** pandas (библиотека для таблиц в Python),
базовая статистика (среднее, разброс, корреляция).

**Готово, когда:** можешь объяснить свой вывод человеку без графиков, одной фразой.

**Скилы под этап:** [подбираются на шаге 3]

**Материалы:** [ссылки]
```

Критерий «готово» — обязателен и должен быть проверяемым. «Изучить pandas» —
не критерий. «Могу объяснить вывод одной фразой» — критерий.

## Шаг 3. Скилы под каждый этап

Для каждого этапа прогони поиск — **фактически, а не по памяти**:

```bash
npx skills find "<ключевые слова этапа>"
```

Названия скилов меняются, индекс устаревает. Не перечисляй скилы по памяти:
то, что было полгода назад, могли переименовать или удалить.

Проверка найденного — по критериям из `skill-sourcing.md` (установки, автор, содержимое).
Ставь **только под текущий этап**. Не ставь всё на пять этапов вперёд: до третьего
этапа человек дойдёт через месяцы, и половина установленного к тому времени устареет.

Запросы, с которых стоит начинать по направлениям:

| Направление | С чего искать |
|-------------|---------------|
| Data Science | `python data analysis`, `pandas`, `machine learning`, `jupyter`, `statistics` |
| Аналитика данных | `sql`, `data visualization`, `dashboard`, `analytics` |
| Machine Learning | `pytorch`, `model training`, `ml evaluation`, `mlops` |
| Frontend | `react`, `nextjs`, `typescript`, `css`, `accessibility` |
| Backend | `api design`, `database`, `authentication`, `backend` |
| DevOps | `docker`, `kubernetes`, `ci-cd`, `deploy`, `terraform` |
| Мобильная разработка | `react native`, `swiftui`, `flutter`, `mobile` |
| Кибербезопасность | `security audit`, `pentest`, `owasp` |

Это стартовые запросы, а не ответы. Что реально найдётся — покажет поиск.

## Шаг 4. Что делать между этапами

Роадмап без обратной связи превращается в список, который забросят. Поэтому:

- После каждого этапа — **разбор**: что построил, что оказалось труднее ожидаемого,
  что переносим в следующий этап.
- Артефакт каждого этапа **сохраняется** — в репозиторий, в папку. Через полгода это
  портфолио, а не воспоминания.
- Роадмап **пересматривается** после второго этапа. Первая версия всегда написана
  человеком, который ещё не знал предмета.

## Материалы: правила

Ссылки — обязательны, но их мало и они конкретны. Три-пять на этап, не двадцать.

Приоритет: официальная документация → бесплатный признанный курс → книга.
К каждой ссылке — одна строка, что там и зачем сейчас.

Проверенные точки входа:

| Тема | Ссылка |
|------|--------|
| Python с нуля | https://docs.python.org/3/tutorial/ |
| Pandas (таблицы данных) | https://pandas.pydata.org/docs/getting_started/ |
| NumPy (числовые массивы) | https://numpy.org/doc/stable/user/absolute_beginners.html |
| Scikit-learn (машинное обучение) | https://scikit-learn.org/stable/getting_started.html |
| PyTorch | https://pytorch.org/tutorials/beginner/basics/intro.html |
| Статистика, курс | https://www.khanacademy.org/math/statistics-probability |
| Jupyter (среда для анализа) | https://docs.jupyter.org/en/latest/start/index.html |
| Открытые датасеты | https://www.kaggle.com/datasets |
| SQL, практика | https://sqlbolt.com/ |
| Веб-основы | https://developer.mozilla.org/ru/ |
| JavaScript на русском | https://learn.javascript.ru/ |
| Git | https://git-scm.com/book/ru/v2 |
| Docker | https://docs.docker.com/get-started/ |

Остальное — под конкретный этап, через поиск, а не из этого списка.

## Тон

Всё, что в `plain-language.md`, действует и здесь, но строже: человек, спрашивающий
«с чего начать», по определению не знает терминологии.

Не говори «выучи pandas». Скажи:

> **Pandas** — библиотека для Python, которая позволяет работать с таблицами данных
> примерно как в Excel, только программой и на миллионах строк.
> → [Первые шаги](https://pandas.pydata.org/docs/getting_started/)

И сразу — зачем она **на этом этапе**, а не вообще.

## Чего не делать

- Не обещать сроки трудоустройства и зарплату. Ты этого не знаешь.
- Не выдавать роадмап до ответов на четыре вопроса.
- Не перечислять двадцать тем «для полноты» — это парализует, а не помогает.
- Не ставить скилы на этапы, до которых человек ещё не дошёл.
- Не называть скилы и курсы по памяти — проверяй поиском.
