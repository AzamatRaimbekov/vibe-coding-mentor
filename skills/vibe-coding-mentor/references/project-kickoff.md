# Новый проект с нуля: восемь этапов

Вход срабатывает, когда папка пустая или в ней нет кода, а человек говорит
«хочу приложение / сайт / сервис», «давай начнём проект», «есть идея».
Порядок жёсткий: этап не начинается, пока человек не пересказал итог
предыдущего своими словами. Стек, дизайн и задачи **не выбираются за него**.

Подготовка (молча): `git init`, если папки нет в git; `scripts/ralph-init.sh`;
скил `claude-automation-recommender` — что ещё нужно этому проекту, ставлю сам.

| # | Этап | Инструмент | Итог этапа (артефакт) | Человек говорит |
|---|------|-----------|------------------------|-----------------|
| 1 | Обдумать вместе | скил `brainstorming` — один вопрос за сообщение: что за продукт, для кого, какая боль, что делает в первую минуту, нужен ли вход, что храним, видно ли с другого телефона; 2–3 подхода с ценой | договорённость, что строим | «строим вот это, потому что…» |
| 2 | Выбрать стек вместе | карточки по правилу из `plain-language.md`, максимум три за раз; **отдельно** для приложения (например React Native + Expo, Flutter, нативно) и **отдельно** для задней части (готовый сервис вроде Supabase, свой сервер, без задней части в первой версии); рекомендация первой с причиной | `docs/stack.md` | «выбрали X, потому что…» |
| 3 | Спека | агент ecc `gan-planner` → экраны, данные и откуда, что делает задняя часть, что НЕ делаем; агент ecc `architect` → схема в чате (до 7 рамок: телефон, задняя часть, данные, вход) | `docs/spec.md` | пересказ спеки |
| 4 | Дизайн-система и экраны | если Stitch подключён (`claude mcp list`, иначе `mcp-setup` ставит сам): `stitch-manage-design-system` → правила вида, `stitch-generate-design` → каждый экран; схема переходов в чате. Нет Stitch: `ui-ux-pro-max` → то же описанием | `docs/frontend/design.md`, список экранов с переходами | «так» на каждый экран |
| 5 | План | агент ecc `planner`: этапы, у каждой задачи — экран или задняя часть, от чего зависит. Первый этап один: экран на телефоне бесплатно + простейшая связь с задней частью, делается при человеке с выводом команд | план в `docs/plan.md`, первый экран виден | «вижу экран, данные пришли вот так» |
| 6 | Задачи | `/prd` → требования на 5–8 задач, `/ralph` → `scripts/ralph/prd.json`; задача = одна сессия; задача про экран ссылается на макет из этапа 4 | `prd.json` | объясняет каждую задачу; не может — делю мельче |
| 7 | Рой и конвейер | независимые задачи (экран и задняя часть под него) — рою через **workflow** с явного разрешения человека: `mobile-engineer` / `frontend-engineer` на экраны (по макетам, `stitch-react-native` если Stitch есть), `backend-engineer` на заднюю часть, после каждого `code-reviewer` + `security-reviewer`; человек видит, кто над чем. Последовательные — Ralph: цикл не запускаю сам, даю команду для отдельного терминала | сделанные задачи в git | запускает `./scripts/ralph/ralph.sh --tool claude 5` |
| 8 | Разбор | каждая задача дифом; что упало; что сказали ревьюеры; совпадает ли экран с макетом | отчёт | вопросы → снова этап 6 |

О платном (сборка в магазин, аккаунт Apple, тарифы сервисов) — до, а не после.
«Работает» — только с выводом команды.

## Промт, который человек вставляет первой репликой

Даю его, когда человек хочет начать проект в другой папке или другой сессии.
Он от лица ученика: не инструкция роботу, а просьба подумать вместе.

```
Привет, Азамат. Я не программист и никогда не делал такое приложение.
Есть идея, но я не знаю, с чего начать и на чём это делать — давай обдумаем
вместе, шаг за шагом. Работай по правилам скила vibe-coding-mentor и веди
меня по восьми этапам из references/project-kickoff.md, не перепрыгивая
и не решая за меня то, что мы ещё не обсудили: обдумать вместе → выбрать
стек вместе (карточками, отдельно приложение и задняя часть) → спека
(gan-planner, architect) → дизайн-система и экраны (Stitch, иначе
ui-ux-pro-max) → план (planner, первый экран при мне) → задачи (/prd, /ralph)
→ рой для независимых задач (разрешаю workflow) и Ralph для остальных
(команду дай мне, сам не запускай) → разбор дифами и словами ревьюеров.
О платном предупреждай до. Первый вопрос — твой.
```
