# Уроки: чему я научился на своих ошибках

**Этот файл я дописываю сам.** Он и есть механизм самообучения: модель не
переобучается, но инструкции, по которым я работаю, накапливают опыт.

Читай его **перед началом работы**, вместе с остальными справочниками.
Урок здесь дороже правила из головы: правило написано в теории, урок — оплачен
реальной ошибкой.

## Формат урока

```
## <Короткое название>
**Дата:** ГГГГ-ММ-ДД
**Что случилось:** факт, без оправданий
**Почему ошибся:** какое допущение оказалось ложным
**Правило:** что делать в следующий раз, проверяемо
```

Часть «почему ошибся» — обязательна. Без неё урок не переносится на похожие
случаи: запомнится частность вместо причины.

## Когда дописывать

- Сказал «готово», а оказалось не готово
- Назвал проблему, которой нет — ложная тревога
- Пропустил проблему, которая была
- Человек поправил меня по делу
- Команда сработала не так, как я ожидал

**Пиши сразу, а не в конце сессии.** В конце вспоминается формулировка, а не причина.

Дописал — скажи одной строкой: `🧠 Записал урок: <название>`. Человек должен
видеть, что я стал точнее — иначе обещание из приветствия остаётся словами.

## Чего сюда не писать

- Ошибки человека — это его путь, а не мой урок
- Разовые случайности без вывода на будущее
- Общие истины из документации — они и так известны
- Больше одного урока на одну ошибку

## Вывод установщика не равен результату
**Дата:** 2026-08-28
**Что случилось:** `npx skills add` напечатал восемь строк с ошибками формата
PromptScript. Выглядело как полный провал установки. На диске при этом всё встало
правильно — ошибки касались чужого формата, к Claude Code отношения не имевшего.
**Почему ошибся:** принял вывод команды за результат команды. Это разные вещи:
установщик рассказывает о своей работе, а не о состоянии диска.
**Правило:** после установки всегда проверять на диске — `ls -d ~/.claude/skills/<имя>`,
`claude plugin list | grep <имя>`, `claude mcp list | grep <имя>`. Не проверил —
не объявляй `✅ Я УСТАНОВИЛ`.

## Проверка наличия файла не понимает замысла
**Дата:** 2026-08-28
**Что случилось:** скрипт диагностики сказал «нет тестовых данных для базы».
Данные были — в `prisma/seed.ts`, а проверка смотрела только в `package.json`.
**Почему ошибся:** проверял одно known место вместо того, чтобы допустить
несколько раскладок. Ложная тревога дороже пропуска: после двух выдуманных
проблем инструмент перестают запускать.
**Правило:** прежде чем объявить отсутствие — проверить альтернативные места.
Сомневаешься — открой глазами, а не докладывай по выводу скрипта.

## Индекс каталога скилов устаревает
**Дата:** 2026-08-28
**Что случилось:** дважды установка падала с «No matching skills found»:
`refoundai/lenny-skills@vibe-coding` (переименован в `ai-assisted-prototyping`)
и `trailofbits/skills@claude-in-chrome-troubleshooting` (реальная папка —
`chrome-mcp-troubleshooting`).
**Почему ошибся:** считал каталог поиска источником истины. Источник истины —
репозиторий; каталог лишь его слепок, снятый когда-то раньше.
**Правило:** установка упала по имени — не сдаваться и не выдумывать. Посмотреть
реальные имена папок:
`gh api "repos/<owner>/<repo>/git/trees/main?recursive=1" --jq '.tree[].path'`.

## Поиск по имени, которое произносят вслух, врёт
**Дата:** 2026-08-28
**Что случилось:** человек попросил проверить «find-skill», «frontend-skill»,
«backend-skill». Скилы с такими именами не существуют — реальные названия
`find-skills`, `frontend-agent`, `backend-engineering`. Проверка по услышанному
вернула бы «нет» на установленном.
**Почему ошибся:** принял разговорное название за имя папки.
**Правило:** проверять по точному имени каталога, а разговорные варианты держать
в таблице соответствий. Отвечая «этого нет» — сначала убедись, что искал верно.
