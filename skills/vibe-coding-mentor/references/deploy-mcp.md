# Инструменты деплоя: что должно быть подключено

Читай этот файл на шаге «Инструменты» — **до** того, как обещать ученику деплой,
работу с БД или генерацию UI.

## Зачем это шаг, а не мелочь

Отсутствующий MCP не даёт ошибку. Агент молча деградирует: вместо чтения реального
лога деплоя пересказывает вероятный, вместо запроса к БД предлагает «примерную» схему.
Ученик получает правдоподобный вымысел и не может отличить его от факта.

**Худшее состояние — не «нет», а «needs authentication».** Сервер числится
подключённым, инструменты видны, но каждый вызов падает. Это выглядит как поломка кода,
и ученик уходит чинить не то.

## Проверка

```bash
claude mcp list 2>&1 | sed 's/ - /\t/' | awk -F'\t' '{print $NF"\t"$1}' | cut -c1-90
```

Четыре состояния, три из них требуют действия:

| Состояние | Что делать |
|-----------|-----------|
| `✔ Connected` | ок |
| `! Needs authentication` | **стоп.** Авторизовать до начала работы |
| `✘ Failed to connect` | сказать вслух, что этой возможности нет; не притворяться |
| отсутствует в списке | предложить установку одной командой |

Дополнительно проверь CLI — они часто закрывают дыру без всякого MCP:

```bash
for c in vercel supabase gh; do printf '%-9s %s\n' "$c" "$(command -v $c || echo НЕТ)"; done
```

## Что именно нужно

### Vercel — деплой, логи, переменные окружения

**Без него ломается:** просмотр логов упавшего билда, статус деплоя, список env-переменных.
Агент начинает угадывать причину падения вместо чтения лога.

- Проверка: `claude mcp list | grep -i vercel`
- Если `Needs authentication` — в **интерактивной** сессии выполнить `/mcp` и пройти OAuth.
  В неинтерактивной (`-p`, хук, cron) OAuth невозможен: скажи об этом прямо и переключись на CLI.
- Если отсутствует: `claude mcp add --transport http vercel https://mcp.vercel.com`, затем `/mcp`.
- **Фолбэк без MCP:** `vercel logs`, `vercel env ls`, `vercel deploy` — покрывает почти всё.
  Проверить: `command -v vercel`.

### Supabase — база, схема, миграции, RLS

**Без него ломается:** чтение настоящей схемы, проверка RLS-политик, применение миграций.
Самая опасная дыра: агент предполагает схему вместо того, чтобы её прочитать, и уверенно
пишет запросы к несуществующим колонкам.

- Проверка: `claude mcp list | grep -i supabase`
- Установка (stdio, нужен personal access token из Supabase Dashboard → Account → Tokens):
  ```
  claude mcp add supabase -- npx -y @supabase/mcp-server-supabase@latest \
    --read-only --project-ref=<PROJECT_REF>
  ```
  Токен передаётся через окружение `SUPABASE_ACCESS_TOKEN`, не в аргументах.
- `--read-only` для учебного проекта — правило по умолчанию. Снимать только под конкретную
  задачу миграции и возвращать обратно.
- **Фолбэк:** `supabase` CLI (`supabase db diff`, `supabase migration list`). Если CLI нет:
  `npm i -g supabase` или `brew install supabase/tap/supabase`.
- Если проект на Prisma без Supabase — этот пункт неприменим, скажи об этом и не тяни лишнее.

### 21st.dev — генерация UI-компонентов

**Без него ломается:** ничего критичного. Это ускоритель, а не зависимость.

- Проверка: `claude mcp list | grep -i 21st`
- Установка: `claude mcp add --transport http 21st https://21st.dev/api/mcp`
- **Осторожно с областью видимости.** Если сервер добавлен на уровне проекта, в соседней
  папке его не будет, хотя ученик уверен, что «он же есть». Проверять надо из той папки,
  где идёт работа. Область смотреть в `~/.claude.json`: ключ `mcpServers` внутри `projects`
  — это локальная привязка, корневой `mcpServers` — глобальная.

### Superpowers — рабочие процессы, а не MCP

**Это набор скилов, не сервер.** В `claude mcp list` его не будет никогда — не ищи там.

- Проверка: `ls ~/.claude/skills | grep -E '^(brainstorming|writing-plans|using-superpowers)$'`
- Должны найтись как минимум `brainstorming`, `writing-plans`, `using-superpowers`.
- Если пусто: `npx skills add obra/superpowers -g -y`
- **Без него ломается:** пропадают `test-driven-development`, `systematic-debugging`,
  `verification-before-completion` — то есть вся дисциплина, на которую опирается этот
  скил. Шаг 4 цикла (красный тест) без них выполняется вручную и разваливается первым.

## Как докладывать ученику

Одной таблицей, до начала работы. Не списком задач — фактом состояния:

```
Vercel     ! нужна авторизация  → /mcp, иначе логи деплоя я не увижу
Supabase   ✘ не установлен      → схему БД буду только предполагать
21st.dev   ✔ подключён
Superpowers ✔ скилы на месте
```

Затем одна фраза о последствии для текущей задачи — и вопрос, чинить сейчас или работать
с ограничением. Ограничение, названное вслух, честно; ограничение, скрытое молчанием, — нет.

## Запреты

- Не начинать деплой, пока нужный сервер в состоянии `Needs authentication`.
- Не пересказывать содержимое логов, которые не прочитаны.
- Не предполагать схему БД, когда доступа к ней нет — сказать «не вижу схему» и спросить.
- Не просить у пользователя токен в чат. Токены задаются через окружение или `/mcp`.
- Не ставить всё подряд «на будущее». Ставим то, что нужно текущей задаче.
