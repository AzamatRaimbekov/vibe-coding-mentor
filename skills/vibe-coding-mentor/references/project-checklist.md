# Чек-лист: что должно быть в проекте

Прогоняй перед новой фичей. Отмечай **есть / нет / рано**. Называй ученику максимум
два пробела за раз — те, что дороже всего обойдутся позже.

Колонка «цена промедления» — это то, что говоришь ученику вместо «так принято».

---

## 1. Воспроизводимость

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| README с командами запуска | `head -40 README.md` | Через месяц ты сам не запустишь проект |
| Lockfile закоммичен | `ls package-lock.json pnpm-lock.yaml yarn.lock` | «У меня работает» — и больше нигде |
| Версия рантайма зафиксирована | `cat .nvmrc; grep -A2 '"engines"' package.json` | Обновление Node ломает сборку без предупреждения |
| `.env.example` со всеми ключами | `ls .env.example && diff <(grep -o '^[A-Z_]*' .env.example \| sort) <(grep -rho 'process\.env\.[A-Z_]*' --include='*.ts' --include='*.tsx' . \| sed 's/process\.env\.//' \| sort -u)` | Новый разработчик (или ты на другой машине) не знает, что задавать |

## 2. Гигиена репозитория

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| Секретов нет в истории | `git log --all -p \| grep -iE '(api[_-]?key\|secret\|password\|token)\s*[=:]\s*["'\''][^"'\'']{8,}' \| head` | Утёкший ключ нельзя «удалить» — только отозвать |
| `.gitignore` покрывает `.env`, `node_modules`, сборку | `cat .gitignore` | Мусор в дифах, секреты в репо |
| Рабочее дерево чистое перед началом | `git status --short` | Смешаешь свою правку с чужой недоделкой |

## 3. Границы кода

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| Домен не знает про UI и БД | `grep -rl 'next/\|react' lib/domain/ 2>/dev/null` — должно быть пусто | Бизнес-логику нельзя протестировать без браузера |
| Валидация в одном месте, не продублирована | Найти схемы: `grep -rl 'z\.object\|zodResolver' --include='*.ts*' .` | Форма и сервер расходятся — баг, который видит только пользователь |
| Серверные действия тонкие | Файлы с `'use server'` — оркестрация, не расчёты | Логику невозможно переиспользовать |

## 4. Тесты

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| Тесты вообще запускаются | `npm test 2>&1 \| tail -20` | Тесты, которые никто не гоняет, — это комментарии |
| Есть хотя бы один happy path на фичу | `ls **/__tests__/` | Не заметишь, что сломал главный сценарий |
| Есть хотя бы один тест на отказ | Ищи `expect(...).rejects\|toThrow` | Ошибки — половина поведения; непокрытая половина |
| Тесты не зависят от порядка | `npm test -- --shuffle` (если поддерживается) | Красный билд без причины, потеря доверия к тестам |

## 5. Данные

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| Схема описана в коде, а не только в голове | `ls migrations/ schema.sql prisma/schema.prisma 2>/dev/null` | Прод и локалка расходятся молча |
| Миграции необратимые помечены | Читать последнюю миграцию | Откат релиза = потеря данных |
| Инварианты защищены на уровне БД | Ищи `UNIQUE`, `CHECK`, `FOREIGN KEY` | Гонки между пользователями пробивают проверки в коде |
| Есть seed для локальной разработки | `grep -r '"seed"' package.json` | Каждый запуск начинается с ручного ввода данных |

## 6. Ошибки и UX отказов

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| Страница 404 | `ls app/not-found.tsx` | Пользователь видит системный текст и уходит |
| Граница ошибок / crash fallback | `ls app/error.tsx app/global-error.tsx` | Белый экран вместо приложения |
| Состояние «нет сети» | Ищи `navigator.onLine` или обработку fetch-ошибок | Приложение молча зависает |
| Ошибки формы видны рядом с полем | Проверить один сложный экран вручную | Пользователь не понимает, почему кнопка не работает |
| Текст ошибки не отражает сырой ввод | Ищи вывод произвольных строк из URL/тела запроса | XSS и фишинг через ссылку |

## 7. Решения и знание

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| ADR на нетривиальные выборы | `ls docs/wiki/decisions/ docs/adr/ 2>/dev/null` | Через полгода никто не помнит, почему так, и переделывает обратно |
| Живая документация фич | `ls docs/wiki/index.md` и `FEATURE.md` рядом с модулями | Знание живёт только в чате, который потеряется |
| Инструкция агенту | `ls CLAUDE.md AGENTS.md .AI.md` | Агент каждый раз изобретает стиль заново |

## 8. Автоматические проверки

| Пункт | Как проверить | Цена промедления |
|-------|---------------|------------------|
| Типы сходятся | `npx tsc --noEmit` | Ошибки всплывают у пользователя, а не при сборке |
| Линт проходит | `npm run lint` | Стиль обсуждается на каждом ревью вручную |
| CI гоняет то же, что и ты локально | `ls .github/workflows/` | «У меня зелёное» перестаёт что-либо значить |

---

## Что «достаточно» на разных этапах

| Этап | Обязательный минимум |
|------|----------------------|
| Учебный проект / прототип | Разделы 1, 2, 4 (хотя бы happy path) |
| Показать людям | + разделы 6 и 8 |
| Реальные пользователи и данные | + разделы 3, 5, 7 полностью |

Не требуй прод-уровня от прототипа — это отбивает желание учиться.
Но раздел 2 (секреты) обязателен всегда, с первого коммита.
