# Службы: что ломается без каждой и как подключить

Порядок в файле — по частоте, с которой вайб-кодный проект в них упирается.

## Подключаю сам — секретов не нужно

### Playwright — глаза на сайт

**Без него ломается:** я не могу открыть готовый сайт и посмотреть, что видит человек.
Проверка «работает» превращается в «должно работать».

```bash
claude mcp add playwright -s user -- npx -y @playwright/mcp@latest
```

Вход не нужен: браузер запускается на этой машине.
→ [документация](https://github.com/microsoft/playwright-mcp)

### Vercel — публикация, логи, переменные окружения

**Без него ломается:** чтение лога упавшей публикации. Агент начинает угадывать
причину падения вместо того, чтобы её прочитать.

```bash
claude mcp add --transport http --scope user vercel https://mcp.vercel.com
```

Дальше нужен **вход в аккаунт** — команда `/mcp` в чате, откроется браузер.
Это единственное, чего я не могу: окно браузера и его аккаунт.
→ [vercel.com/account](https://vercel.com/account)

**Запасной путь без MCP:** команды `vercel logs`, `vercel env ls` — закрывают почти всё.

### 21st.dev — готовые куски интерфейса

**Без него ломается:** ничего критичного. Ускоритель, а не зависимость.

```bash
claude mcp add --transport http --scope user 21st https://21st.dev/api/mcp
```

→ [21st.dev](https://21st.dev)

## Без человека нельзя

### Google Stitch — рисование макетов экранов

**Что это:** сервис Google, который рисует макет экрана по описанию словами.
Как дизайнер, которому объяснили задачу на словах и он принёс эскиз.
**Чем платим:** нужен Google-аккаунт, и макет — это картинка и разметка,
а не готовое приложение; код всё равно писать.
→ [stitch.withgoogle.com](https://stitch.withgoogle.com)

**Без него ломается:** девять скилов Stitch, которые стоят на этой машине
(`stitch-generate-design`, `stitch-react-components` и остальные), не работают вовсе —
они все обращаются к этому серверу. Стоят, видны, при вызове падают.

**Почему я не могу сам:** адрес сервера выдаётся персонально, в конце входа
в Google-аккаунт. У меня нет ни окна браузера, ни его аккаунта.

**Что делает человек:**
→ [инструкция по подключению](https://stitch.withgoogle.com/docs/mcp/setup/) —
войти, получить адрес сервера, вернуться и сказать мне его. Команду добавления
я напишу сам.

### Supabase — настоящая схема базы данных

**Без него ломается:** самая опасная дыра. Агент предполагает, как устроена база,
и уверенно пишет запросы к колонкам, которых нет.

**Почему я не могу сам:** нужен личный токен доступа, а токены нельзя пересылать
в чат — это утечка. Токен передаётся через переменную окружения
`SUPABASE_ACCESS_TOKEN`.

```bash
claude mcp add supabase -- npx -y @supabase/mcp-server-supabase@latest \
  --read-only --project-ref=<PROJECT_REF>
```

`--read-only` для учебного проекта — правило по умолчанию: так агент физически
не может испортить данные. Снимать только под конкретную задачу и возвращать обратно.

→ [страница токенов](https://supabase.com/dashboard/account/tokens)

**Запасной путь:** `supabase` CLI — `supabase db diff`, `supabase migration list`.

## Область видимости — частая ловушка

Сервер, добавленный на уровне проекта, в соседней папке не существует, хотя человек
уверен, что «он же есть». Проверять надо из той папки, где идёт работа.

Флаг `--scope user` в командах выше — как раз чтобы сервер был везде, а не в одной папке.
